# 02 · 从一段资讯出发：搜素材、核事实

用户给的资讯（一段话、一条链接、一张截图里的文字）只是起点，它本身可能有错、过时或者是二手转述。目标是在 10–20 分钟内拿到：一手出处、2–3 个能砸在屏幕上的硬数字、一个对比对象、一句真实原话（可选）。

## 搜索顺序

1. **拆资讯**：列出实体（公司、产品、人）、时间、数字、动作（发布、降价、收购、禁令、财报）。今天的日期在系统提示里，判断它是不是「新闻」。
2. **找一手出处**（WebSearch，必要时 `mode: extended`；读页面用 WebFetch，403 就用内置浏览器 `get_page_text`）：
   - 官方博客、新闻稿、产品页、发布会、技术报告或论文、财报和公告（交易所/SEC）、监管文件。
   - 社交媒体原帖只认官方账号或当事人本人。
3. **交叉核对**：2 家以上可靠媒体（Reuters、Bloomberg、The Verge、TechCrunch、财新、36氪等）是否一致；不一致就以一手为准，并在事实表里写出差异。
4. **补对比**（爆点大多来自对比）：
   - 同一指标的上一代、竞品、行业均值（价格、性能、参数、份额、用户数）；
   - 口径必须一致：同一基准测试、同一币种、同一时间。
5. **补背景**（一句话够用）：为什么这件事重要、之前发生过什么。
6. **原话**（可选）：发布会或官方博客里的原句，记下出处和时间。

## 事实表（`发布文案.md` 文末，也写进 README）

| 说法 | 数值/原话 | 口径 | 状态 | 出处 |
|---|---|---|---|---|
| 新模型 API 价格 | $X / 百万 token | 输入价，官网价目表 | 已官宣 | 链接 |
| 竞品价格 | $Y | 同上 | 已官宣 | 链接 |
| 「X 将在年底发布」 | — | — | 传闻（仅一家报道） | 链接 |

状态只有三档：**已官宣**（一手出处）、**多家报道**（≥2 家可靠媒体，无一手）、**传闻**。传闻只能用「据传」「还没官宣」，标题加「？」，不能当成爆点的唯一证据。

## 资讯本身有问题时

- 一手出处和用户给的说法不符：按一手做，交付时告诉用户哪里不一样。
- 找不到任何可靠出处：先告诉用户，问要不要按「传闻」口径做，或者换题。
- 涉及股价、投资：只说发生了什么，不做买卖建议，台头 `note` 写「不构成投资建议」。

## 画面素材

- **默认全用代码画**：资讯卡（只写来源名称文字，不仿制对方 logo 和版式）、参数对比、VS、柱状图、引语卡、示意图。这样不涉及版权，也最快。
- **真实图片/视频**（产品图、发布会画面）：先问用户，列出文件名、来源、大小、许可。只用明确允许的：官方媒体资料库（press kit）注明可用于报道的、Wikimedia Commons 的公有领域/CC。画面角落署名。
- **截图**：不贴网页或 App 的真实截图（版权和肖像），用资讯卡复述要点。
- **人物**：不用真人照片做表情包、不配贬损性文字；需要人物时用名牌卡（名字＋身份）。
