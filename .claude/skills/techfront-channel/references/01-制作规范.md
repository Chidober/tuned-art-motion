# 01 · TechFront 制作规范（v1，来自 TF-20261010-01 的 A-v2、A-v3、B-v1 三轮）
每条后面的〔〕写出处：brief = 制作单 brief-v2；审 v2 / 审 v3 = 两轮审片报告；规范 = playbook-v1（用户已采纳的两条）；实测 = 制作时的测量。

## 1 读制作单
- 制作单会说明：选题卡（含"制作前事实核对"）、语言、版本（A 竖版短片 / B 横版长片）、平台、红线、交付清单。**事实核对一节的更正优先于卡片前文**〔brief〕。
- 动手前先把硬约束列成清单：标题原文、必须分开讲的案例、不能提的内容、哪些说法必须注明"某方称"、交付文件名。最终回复要逐条回应。
- 返工单只改点名的项目（例："只改第 1–5 项和建议第 9、10 项"），其余项即使看到问题也不动，写进遗留问题〔rework-v3〕。

## 2 事实、归属、推测
- 只讲标为"事实/已核实"的条目。一手来源里有、但核对表里没有的说法，也不讲。例：Anthropic 原文里"任务含糊或无法完成"的解释，以及"看法可能改变"，都不在 23 条里，所以没有用〔brief B〕。
- 机构的判断要写成机构说的：口播用 "Anthropic says / calls / points to"；画面用 `ANTHROPIC:` 标签，和结论放在同一块、同样醒目（两行等大反白块）。小字注脚不算〔审 v2 第 3、4 项〕。
- 一种解释不能说成唯一原因：写 "Anthropic offers one possible explanation… it hasn't said this is the only cause"〔审 v2 第 8 项、审 v3 B、brief B 第 3 条〕。
- 经媒体转述的警方或官方说法："police said … (via NYT)"、"Al Jazeera reports that police called…"。日期、"两个月"这类细节都要标注〔brief〕。
- 引语要写全出处。原句以 "From the transcript," 开头的，不要截掉〔审 v2 第 7 项〕。
- 推测要单独成段，口播说 "this next part is our interpretation"，画面标 "OUR INTERPRETATION (speculation)"；不知道的事说 "what we don't know yet"。
- 红线：
  - 传闻不讲，任何对外文件都不出现相关字眼；
  - 不暗示有意作恶（只说 submitted an invented tip）；
  - 不提受害者、案件细节、街道名；
  - 只点名已公开的那个机构；
  - 不说"第一次"这类没核实的定性；
  - 不夸大风险〔brief〕。
- 两个以上的案例要分开讲：分镜、分卡片，画面上写 "a DIFFERENT model / not <模型名>"〔brief v2〕。

## 3 标题、钩子、平台剪辑
- 标题用制作单原文。YouTube 标题**不加后缀**，因为后缀可能带出错误归属（v2 的后缀把案例 2 也算到了 Claude 头上）；关键词放在简介和标签里〔审 v2 第 5 项〕。
- 第 0 帧要有完整片名，每个平台版都要；0.3–0.6 s 内开口。
- 一个母版按平台各剪一版〔规范〕：
  - YouTube 版从署名开场开始（更清楚，例 "Anthropic says one of its AI models…"）；
  - TikTok 版从钩子那句前 0.15 s 开始（更直接），片名卡要一直保留到钩子说完，这样 TikTok 第 0 帧仍有片名。
- 钩子承诺什么，正片要兑现（例：钩子说"填了警方线索表"，正片要讲清怎么填的、结果如何）。
- TikTok 文案不用 🚨 这类耸动 emoji〔审 v2 第 14 项〕。

## 4 版式与画面
### 竖版（1080×1920）平台版
- 字幕框底边 ≤ 1500，右边界 ≤ 900；画面内容整体缩到 0.86，(70, 230) 映射到 (62, 230)，内容最低处约 1271，与字幕框错开〔审 v2 第 1、2 项，A-v3 实测〕。
- 母版字幕可以留在 v2 的位置；平台版单独渲染一个版式（例 `eras_<film>_plat.js` 设 `window.SUB_SAFE`）。
### 横版（1920×1080）
- 一个版式出所有版本：关键文字和字幕框都在 x ≤ 1600 以内（在 TikTok 上横版居中留黑显示，右侧按钮列会压到画面右侧约 17%）。字幕框底边 y = 1000；关键内容 y ≤ 880。x > 1600 只放实拍或照片〔B-v1〕。
### 两种都适用
- 屏幕上只放关键词和数字，整句交给口播和字幕〔TF-G-001 假设 4〕。
- 每镜开口时画面上要有大块内容（标签块、照片、实拍）：只有一行小字的镜头开头，会被 blackdetect 判成黑场〔审 v2 第 10 项，A-v3、B-v1 实测〕。
- 黑场 ≤ 0.2 s：渲染前用 0.05 s 步长扫一遍所有镜头边界，渲染后在成片上跑 blackdetect（d=0.1、pix_th=0.10、pic_th=0.98）。
- 开头 3 秒：终端或说明文字只留 1–2 行（常驻来源行＋最新一条）〔审 v2 第 9 项、审 v3 D〕。
- 画面右边界：较长的文字行要逐个确认没有超线（审 v3 A：超出 7px 也会被抓）。

## 5 字幕、读音、配乐
- 烧录字幕：竖版每行 ≤ 32 字符，横版 ≤ 48；没有一个词单独成行（`fix_orphans.py`）；条与条不重叠；单条至少约 0.9 s〔审 v2 第 11、15 项〕。
- CC（`*.en.srt`）：每条 ≤ 2 行 × 42 字符，写正确拼写；TikTok 版的时间整体平移。
- 读音（edge-tts）：
  - `<phoneme>` 用不了：走正常接口时标签会被当成文字念出来，原样发送则服务端拒绝。这一点 A-v3 已验证，不用再测。
  - 用替换拼写，只写在 `口播稿.json` 的 `say` 字段里，例：Claude → "Clawed"，Anthropic → "an-throppick"。
  - 每一句都用声学检查（第二音节重音）决定用不用替换，替换后反而变差的句子保留原拼写（A-v3 L10、B-v1 多句）。
  - 改了 `say` 后：字幕对齐要支持"一词换一词"（项目内 `subs.py`）；画面锚点不要挂在被替换的词上（A-v3 把 L06 的锚点改挂到 "says"）。
  - 逐字稿和对外文件里不能出现替换拼写〔审 v3 必改 1〕。读音说明放在内部文件里。
  - 读音要请人耳确认；模型试听只能当参考〔审 v3〕。
- 配乐：开头压低 3–4 dB，覆盖母版前 3 秒和 TikTok 版前 3 秒（TikTok 起点要算进去）；整体响度 −16 LUFS，真峰值 ≤ −1 dBTP。

## 6 交付物（文件名 `TF-…-<A|B>-vN_*`）
- 成片：
  - `_master_clean.mp4`（无水印）
  - 平台版 `_tiktok.mp4`
  - `_ytshorts.mp4`（竖版）或 `_youtube.mp4`（横版）
  - 720p 预览
- 字幕：每个版本的 `.en.srt`（CC）和 `_burned-subs.srt`（烧录字幕时间）。
- 封面：每个平台一张，另出缩略图；TechFront 角标不要放在右下（平台界面区）〔审 v2 第 13 项〕。
- 文档：`transcript.md`、`sources.md`（时间点 ↔ 来源）、`fact_table.md`、`发布文案.md`、`qa_report.md`、README；返工版另加 `rework_vN.md`。

## 7 版本管理
- 返工：`cp -R` 上一版本得到 vN+1，记录旧版本成片的 SHA-256；之后只改新目录。从旧版复制来的成片不要改名冒充新版。
- 复制过来的脚本先把路径全部改成新版本，并加防护：路径里出现其他版本号就退出，并检查每个输出都在本版本目录下。A-v3 的 `render_cuts.sh` 复制自 A-v2，原样跑就会覆盖 v2。
- 写文件被权限或隔离保护拦下时：停下，在返工记录和回复里写明，不要换一种写法绕过去。

## 8 对内 / 对外
| 对外（可以发） | 只对内 |
|---|---|
| 成片、`*.en.srt`、封面、`发布文案.md` 里的标题、简介、标签 | `transcript.md`、`sources.md`（可能含被排除内容的网址）、`fact_table.md`、读音文件、测试音频、检查帧 |
