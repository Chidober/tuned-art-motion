# 04 · 发布数据回填与风格迭代
**现状（2026-10-10）：还没有发布数据。** 本文规定数据到了以后怎么接入、怎么判断、怎么改规范。下面的阈值都是【建议】，第一次用之前请用户确认或调整。

## 1 数据从哪来、怎么填
1. **导出**：TikTok Studio（单条视频分析）、YouTube Studio（高级分析 → 视频，按内容类型分 Shorts 和长视频）。截图不算数，要数值。
2. **填表**：每条视频、每个观察窗口填一行到 `data/metrics.csv`，列定义见 `data/metrics_template.csv`。不要编数字，没有的字段留空。
   - `video_id`：制作编号＋版本＋平台，例 `TF-20261010-01-A-v3_tiktok`
   - `platform`：`tiktok` / `youtube`；`format`：`vertical_short` / `horizontal_long` / `yt_short`
   - `window`：`24h` / `72h` / `7d`（从发布时刻算）
   - `experiment`、`arm`：参与的实验和组别（例 `EXP-002`、`H2`）；不参与就留空
   - 指标：`views`、`avg_watch_s`、`avg_watch_pct`、`retention_3s_pct`、`completion_pct`、`likes`、`comments`、`shares`、`saves`、`follows`、`search_traffic_pct`、`impressions`、`ctr_pct`（平台给不出的留空）
   - `published_at`（含时区）、`source`（从哪个后台、什么时候导出的）
3. **跑报告**：`python .claude/skills/techfront-channel/scripts/metrics_report.py`。它会按 平台＋形态＋窗口 分组，算每条视频相对该组基线（近 10 条的中位数，不够就用已有的全部）的倍数；还会按实验分组汇总，并给出"可以下结论 / 还差几条"。

## 2 比较口径（硬规则）
- 只在**同平台、同形态、同窗口**之间比较。TikTok 竖版不和 YouTube 长视频比；24h 不和 7d 比〔TF-G-001 §4〕。
- 一次只改一个变量。实验组和对照组的其他条件尽量一致：选题类型、时长段、发布时段。
- 每组至少 **3 条**视频才下结论〔playbook 实验纪律〕；2 条以下只记录，不下结论。
- 用相对基线的倍数（或中位数之差），不用单条绝对值。早期账号的波动很大。

## 3 决策规则（【建议】，首次使用前请用户确认）
| 结果 | 条件 | 动作 |
|---|---|---|
| 升级为【数据支持】 | 每组 ≥ 3 条；主指标中位数领先对照组 ≥ 20%；同一方向在 72h 和 7d 两个窗口都成立 | 在 `style_changelog.md` 提议，用户批准后改 `03-视频风格.md` 和制作规范版本 |
| 降级或删除 | 每组 ≥ 3 条；主指标落后 ≥ 20%，或审片判定伤及信任（被举报、事实问题） | 同上 |
| 继续观察 | 差距 < 20%，或方向不一致 | 记一笔，继续收集数据；最多 6 条，之后视为"无差别"，选成本低的做法 |
| 立即暂停 | 出现事实错误、被平台限流或下架、评论区集中指出误导 | 不等样本量；先停用相关做法，报告用户 |

主指标在 `experiments.csv` 的 `primary_metric` 列登记（例：EXP-002 用 `retention_3s_pct`，EXP-003 用 7d `views` 和 `search_traffic_pct`）。

## 4 改规范的流程
1. 由 `metrics_report.py` 的输出加上你的判断，形成提议，写进 `data/style_changelog.md` 一条："日期 / 规则编号 / 原等级 → 新等级 / 证据（视频 id、窗口、数值）/ 提议人"。
2. 用户批准后再改 `03-视频风格.md` 和 `experiments.csv` 的状态，并给制作规范加版本号（例 v1 → v1.1）。没批准就不改正文。
3. 下一支片按新版本做，在 README 里写明用的是哪个规范版本。

## 5 和制作的衔接
- 每支片交付时，在 README 写明它参与了哪个实验、哪一组，并在 `metrics.csv` 预先填好 `video_id / platform / format / experiment / arm / published_at`（指标留空），发布后再补数。
- 审片发现的问题（信任、事实类）也是数据：写进 changelog，直接影响【数据支持】的判断。
