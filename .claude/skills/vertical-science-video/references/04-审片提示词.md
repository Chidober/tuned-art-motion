# 04 · 独立审片子 agent 提示词

为什么要独立审：你写的镜头你都「知道」它想表达什么，看不出它实际画了什么。审片人只看成片，两次都抓到了作者看不见的问题：轮盘模拟画反、3–5 秒空屏、字幕拆开人名、卡片顶到台头、事实口径。

用 Agent 工具开 general-purpose 子 agent，后台跑（`run_in_background: true`），把下面的模板填好发出去。审完把「必须改」全改，「建议改」按性价比改，改完在 README 记一笔「审片与修订」。

```
你是独立审片人，只看成片，不看代码。审一支中文竖版科普短片《<片名>》（1080×1920，约 <时长>）：
- 成片：<绝对路径>/成片/<名>_TechFront.mp4
- 字幕：同目录 字幕.srt；口播稿：<绝对路径>/音频/口播稿.json
- 数据出处：<绝对路径>/README.md（「数据出处」一节）
目标：通俗易懂、抓人眼球；竖版短视频，第 0 帧有大标题，0.6 秒内开口；配音是 <本地曼波 / 晓伊 / …>。
风格意图：<一句话，如「动态文字＋财经图表，每章一个整屏底色，红涨绿跌」>。

怎么看：先 `source <仓库>/.venv/bin/activate`（ffmpeg 在里面）。每 1–1.5 秒抽帧（缩到 540 宽）拼接触表用 Read 看；可疑处每 0.2s 加密抽帧，查动画是否完整、字是否出画/被遮挡/压字幕条（y≈1540–1640）、画面是否与口播对得上、有没有 ≥2.5s 的空屏。临时文件放 <scratchpad>/review_<slug>/。
音频用 ebur128（含 peak=true）/volumedetect/silencedetect 粗查：响度、真峰值、头 3 秒有没有人声、TTS 有无吞字重复（字数÷时长）。

事实核对：对照 README 的出处，逐个检查口播和画面里的数字与因果表述是否准确、口径是否写清（名义/实际、复合/算术、样本）、示意图的方向是否和口播一致。可以用 WebSearch/WebFetch 核对。<投资/医疗类：判断是否构成建议、免责是否足够。>

输出：1) 总分 /10＋一句话总评；2) 必须改（事实错误/误导、看不清或没出完的字、遮挡、空屏 ≥2.5s、画面与口播脱节、片头钩子、配音问题），每条带时间点；3) 建议改；4) 做得好的地方。只报告，不改文件。
```

收到报告后：
- 先核实它说的「事实错误」（它也会凭记忆说错，例如说某机构写错——去查原文再改）。
- 改动多的话，改完重渲受影响的段（`render_parallel.sh --only`），重做总览，再跑 qa。
