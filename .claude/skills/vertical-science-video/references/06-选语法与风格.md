# 06 · 先选解说语法和艺术风格，出标题图，用户点头再做片

**为什么有这一步**：2026-10 连着几支片都用了动态文字（pop kit，黄底砸字＋数据图）。原因是它最省事、kit 现成，不是因为选题需要它。用户原话：「现在的视频风格还是和之前一样……根据选题选择符合的风格，先做一张标题图我看看风格，直到我同意后开始做视频」。

风格是用户的决定，不是 agent 的默认值。做一整片再被否掉，配音、几十个镜头、渲染全部白做。一张标题图几分钟就能出，让用户先拍板。

## 两个维度，分开选

1. **解说语法**：画面怎么讲道理。来自仓库 `references/09-视频动画语法.md` 的 9 张卡，按口播在干什么来选：

| 语法 | 选题里有这种内容就选它 | 本 skill 现成 kit／参考 |
|---|---|---|
| y1 Kurzgesagt 扁平 | 尺度、「里面是什么」、机制系统（宇宙、细胞、粒子、芯片内部） | 横版 `nobel2026_icecube/代码工程/nobel/`、`nobel2026_optogenetics/…/opto/`；竖版要改坐标 |
| y2 Vox 拼贴 | 历史、人物、文献、新闻、原话，「看这一句」 | `collage_kit.js`（`nobel2026_chirality`） |
| y3 白板手绘 | 推理链、「为什么」、一步步推导 | `board_kit.js`（`andy_bill_v2`，竖横通用：一块大白板、每镜一页、相机平移、手写字到切点前自动写完）；`demos/y3_whiteboard` |
| y4 故事型简笔角色 | 第一人称经历、日常场景、「你是不是也……」 | `demos/y4_storytime` |
| y5 动态文字 | 清单、金句、几个要点、章节卡 | `pop_kit.js`（`stock_gamble`、`andy_bill`） |
| y6 讲解员 | 商业史、产品机制，需要一个角色串场带情绪 | `动画语法/y6_presenter_explainer.md` |
| t1 3Blue1Brown | 数学、算法、公式、一个概念变成另一个 | `demos/t1_3b1b` |
| t2 发布会界面 | 产品、参数、版本、教程步骤 | `demos/t2_keynote_ui` |
| t3 财经图表 | 走势、份额、对比，观众会较真的数字 | `pop_kit.js` 的 `P.bars` 等；`demos/t3_finance_chart` |

   - 一支片可以以一种语法为主，个别段落借用另一种（例如 y2 为主，数据段用 t3 画图）。主语法要说得出理由：这个选题的核心内容是什么形态。
   - y5 不是兜底：只有选题本身就是「清单／金句／要点」时才选它。

2. **艺术风格**：画面长什么样（配色、笔触、质感、字体气质）。从仓库 `references/风格配方/INDEX.md` 的 35 种风格挑（★★★ 的可以直接用），或者用现成 kit 的皮肤：
   - 跟选题的时代或文化挂钩：讲电脑史选 8-bit 像素或 90 年代界面，讲中国古代科技选水墨／敦煌，讲苏联航天选构成主义，讲赛博／互联网选蒸汽波，讲光学选新海诚光影或印象派。
   - 跟情绪挂钩：揭秘、阳谋这类选题选暗色、高对比；温和的生活科普选纸感、手账、水彩。
   - 风格配方卡是为「艺术史复刻」写的，用在科普片里时保留它的渲染器和配色，版面仍然守竖版版面带（`02-竖版风格与版面.md`），字幕条、台头、水印照旧。

## 和最近几支拉开差别

开工前看 `projects/.science_log.tsv`（每支一行：日期、slug、主语法、艺术风格、kit）。

- 主语法和艺术风格都不要和上一支相同，除非选题强烈需要。需要的话，在推荐理由里说明为什么。
- 用户点名的风格不受这条限制。
- 用户确认后，往日志里追加一行。

## 标题图怎么出

1. **先做调研**：调研和事实表照 `01` 做完。选风格要知道这个选题里有什么材料：有没有历史照片、数据、人物、机制。
2. **写方案**：写 1 个推荐方案，必要时再给 1–2 个备选。每个方案三行：
   - **语法**＋为什么适合这个选题；
   - **艺术风格**＋为什么；
   - **标题文案**：第 0 帧的大标题和 L00 要念的那句。
3. **建工程，只写片头标题镜**：`new_project.sh` 建工程（模板段落表只有 `s01`），按方案写 kit 皮肤和 `s01`，坐标规则照 `02`：
   - 第 0 帧标题完整可见；
   - 主体在内容带里；
   - 右上角留给水印。
   - 备选方案各用一个 film 名（`xxA`、`xxB`），共用一个工程。
4. **渲标题图**：
   ```bash
   python .claude/skills/vertical-science-video/scripts/title_preview.py projects/<slug> <film> --title "<L00 念的标题句>" [--sizes 1080x1920,1920x1080] [--tag A]
   ```
   - 第 0 帧＝封面；2.2 秒左右＝人声念完、动效到位的样子。
   - 没配音时脚本会写一份占位时间轴。
   - 要横版就同时出横版。
5. **交给用户，然后停下**：
   - 用 SendUserFile 发 `渲染/标题图/<tag>_对照.jpg`；
   - 回复里写方案三行和备选；
   - 问用户用哪个、要改什么。
   - **等用户明确同意前**，不配音、不写别的镜头、不渲整片。可以先写口播稿草稿，但先不配音：风格可能会影响稿子的写法，比如拼贴风要「看这一句」的原话。
6. **用户要改就改**：改完重出标题图，直到用户说可以。用户否掉的方向，记进 README 的「风格决定」一节。
7. **用户同意后**才往下走：写稿、配音、写镜头、渲染。片头镜就用确认过的那一版，不要重写。

## 不适用的情况

- 用户说「直接做」「不用看样」「沿用上一支的风格」，就跳过等待。这时在回复里写一句「沿用了 X 风格」。
- 给已经做好的片子出英文版、改版：风格已定，跳过。
